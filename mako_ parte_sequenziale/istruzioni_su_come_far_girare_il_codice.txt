1) Altri file da modificare?
✅ A) include/config.h

Devi aggiungere un flag tipo:

bool use_cpu = false;


e (se vuoi) anche parametri CPU come dedup_stride ecc. ma non è obbligatorio.

✅ B) src/main.cu

Devi aggiungere il parsing CLI di un’opzione, ad esempio:

--cpu → cfg.use_cpu = true

--gpu (opzionale) → cfg.use_cpu = false

Se non lo fai, puoi comunque impostare cfg.use_cpu = true a mano per test, ma per benchmark è meglio via CLI.

✅ C) Build: includere i nuovi .cpp CPU nel comando nvcc

Hai creato diversi file CPU .cpp (dedup, compaction, ahash, hist, candidates, query_ahash, sad_batch).
Questi devono essere compilati e linkati insieme.

Quindi devi aggiornare:

build.sh

(e/o il file compiling)

3) Cosa cambia nel modo in cui fai run?
Prima

Lanciavi tipo:

./sea ./database/ ./newDB/ ./database/video3/frame_000242.raw --topk 50 --verbose

Adesso

Hai due modalità:

GPU (uguale a prima)
./sea ... --verbose


(default: use_cpu=false)

CPU (nuovo)
./sea ... --cpu --verbose


E la differenza è:

GPU → usa CUDA per dedup, compaction, hash, hamming, candidates, SAD

CPU → fa gli stessi passi ma in sequenziale (niente cudaMalloc / kernel)

4) Una cosa importante: i benchmark devono essere “fair”

Se fai confronto CPU vs GPU:

stessa dimensione chunk

idealmente stessa build del DB (o rigeneralo in entrambe le modalità)

Se vuoi confronto “puro kernel”, devi anche decidere se includere:

costo copia H2D/D2H
